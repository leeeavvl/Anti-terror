# Risk Watchlist

Инструмент раннего выявления рисков вовлечения в экстремистскую/террористическую
деятельность для специалистов (психолог, инспектор ПДН, модератор). Специалист явно
добавляет публичный источник (паблик/канал/аккаунт) в watchlist по ссылке/идентификатору;
приложение периодически опрашивает официальный API платформы, находит новые публичные
посты и формирует объяснимый сигнал риска для специалиста.

## Жёсткие ограничения (встроены в архитектуру, не только описаны)

- Мониторится только то, что явно добавлено в watchlist — автопоиска источников в коде нет.
- Только публичные посты/комментарии — интерфейс коннектора (`app/connectors/base.py`)
  содержит ровно один метод, читающий посты; чтения переписки в системе нет физически.
- Никаких автоматических санкций — ревью сигнала специалистом меняет только локальную БД,
  ни один коннектор не вызывает никаких "действий" на платформах.
- `app/connectors/generic_api.py` всегда делает только GET-запрос (метод не берётся из
  конфига), чтобы конфигурацией нельзя было превратить универсальный REST-клиент в
  поисковый или совершающий действия инструмент.

**Важно:** список маркеров риска в `app/risk_engine/rules.py` — иллюстративный пример
механизма скоринга, а не готовый рабочий лексикон. Перед любым реальным использованием
список маркеров должны сформировать и утвердить квалифицированные специалисты.

## Запуск

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python main.py
```

Откроется браузер на `http://127.0.0.1:8000`. При пустой базе автоматически создаётся один
демо-источник с `connector_type=mock` (переключается через `SEED_DEMO_SOURCE=0`), чтобы
на защите не было пустого экрана — но и он в системе ровно потому, что явно записан в
watchlist, как и любой другой источник.

### Запуск через Docker

```bash
docker build -t risk-watchlist .
docker run -p 8000:8000 \
  -v "$(pwd)/data:/app/data" \
  --env-file .env \
  risk-watchlist
```

`-v .../data:/app/data` сохраняет базу данных между перезапусками контейнера,
`--env-file .env` передаёт токены (VK_TOKEN, TG_BOT_TOKEN и т.д.) — сам файл `.env`
в образ не попадает (см. `.dockerignore`). В контейнере не открывается браузер
автоматически (`OPEN_BROWSER=0`) — приложение доступно на `http://localhost:8000`.

## Подключение реального API — ВКонтакте

Встроенный коннектор `app/connectors/vk.py` использует официальный метод VK API
`wall.get` — читает только публичную стену указанного паблика/аккаунта (посты
самого владельца страницы, `filter=owner`), не читает сообщения и ничего не
пишет на платформу.

1. Получите токен доступа на [vk.com/dev](https://vk.com/dev) (токен пользователя,
   сообщества или сервисный токен) с правом чтения стены (`wall`).
2. Задайте его в `.env` (см. `.env.example`), например:
   ```
   VK_TOKEN=ваш-реальный-токен
   ```
3. В `/watchlist` выберите способ подключения «ВКонтакте — официальный API»,
   укажите ссылку на паблик (например, `https://vk.com/название_паблика`) и имя
   переменной окружения с токеном (по умолчанию `VK_TOKEN`) — без ручного JSON.

Если переменная окружения не задана или VK API вернул ошибку — коннектор пишет
понятную запись в лог и пропускает опрос этого источника; остальные источники
(включая demo/generic_api) продолжают опрашиваться независимо.

## Подключение реального API — Telegram

Встроенный коннектор `app/connectors/telegram.py` использует официальный Bot API
(метод `getUpdates`, события `channel_post` и `message`) — читает публикации из
каналов и сообщения из групп/супергрупп, куда бот добавлен администратором.
Коннектор не отправляет сообщений, не удаляет их и никак иначе не действует от
имени бота.

1. Создайте бота через [@BotFather](https://t.me/BotFather) в Telegram и получите токен.
2. Добавьте бота администратором в целевой публичный канал, группу или супергруппу:
   - для **канала** — без прав администратора Telegram вообще не отдаёт боту посты
     (у ботов в каналах не бывает роли «просто участник»);
   - для **группы/супергруппы** — права администратора автоматически снимают
     «приватный режим» Telegram, при котором бот иначе видит только сообщения
     с командами или упоминанием себя, а не все сообщения подряд.
3. Задайте токен в `.env`, например:
   ```
   TG_BOT_TOKEN=ваш-реальный-токен-бота
   ```
4. В `/watchlist` выберите способ подключения «Telegram — официальный Bot API»,
   укажите ссылку на канал/группу (например, `https://t.me/название`) и имя
   переменной окружения с токеном (по умолчанию `TG_BOT_TOKEN`).

**Комментарии под постами канала.** У Telegram комментарии физически живут не в
самом канале, а в отдельном привязанном чате — «группе обсуждений». Коннектор
сам узнаёт (через `getChat`), есть ли у канала такая группа, и если да —
дополнительно читает сообщения из неё как комментарии к постам этого источника.
Единственное условие: бота нужно добавить администратором **в оба чата** —
в сам канал и отдельно в его группу обсуждений (Настройки канала → Обсуждение →
открыть группу → добавить туда бота администратором так же, как в канал).
Если группы обсуждений нет или бот в неё не добавлен — коннектор просто не
найдёт комментарии, но посты канала продолжат читаться как обычно.

Ограничение: источник определяется по публичному `@username` чата — приватные
группы без публичной ссылки этим способом не подключить.

Важно про историю: Bot API не отдаёт задним числом старые сообщения — коннектор
увидит только то, что появится в чате уже **после** того, как бота туда добавили
администратором.

Коннектор не хранит отдельный курсор (offset) в Telegram — как и остальные
коннекторы проекта, он просто фильтрует полученные посты по дате (`since`) и
полагается на дедупликацию по `external_id` при сохранении. Для небольшого
числа каналов это надёжно и просто; для очень активных каналов с большим
объёмом сообщений эффективнее вести offset, но это осознанно оставлено за
рамками референсного коннектора.

## Мониторинг отдельной веб-страницы (блоги, новостные сайты)

Для платформ без API вообще (не только соцсетей) есть коннектор `app/connectors/webpage.py`
— он не использует никакой API, а просто скачивает указанную публичную страницу обычным
HTTP-запросом (как браузер) и следит, меняется ли её текст со временем. В `/watchlist`
выберите способ подключения «Публичная веб-страница по ссылке» и укажите точный адрес —
токен и конфиг не нужны.

**Ограничение, о котором стоит знать:** это работает только для сайтов, отдающих текст
прямо в HTML (обычные серверно-рендерящиеся блоги/новости). Сайты, которым для показа
контента нужен JavaScript или авторизация, этим способом прочитать нельзя — например,
**Яндекс.Дзен не подходит**: проверено вручную, там даже на публичную статью сайт отвечает
редиректом на форму единого входа (`sso.passport.yandex.ru`) ещё до отдачи какого-либо
содержимого, у Дзена нет официального API для чтения статей сторонними приложениями. Это
не ограничение данного коннектора, а свойство самого сайта — обходить эту защиту (например
эмуляцией залогиненного браузера) коннектор сознательно не пытается: это вышло бы за рамки
«чтения публичной страницы» и потребовало бы реальных учётных данных пользователя
платформы, которые в этом проекте никогда не обрабатываются.

Из-за того, что у одиночной страницы нет понятия «список новых постов» (в отличие от ленты
канала), коннектор реагирует на *любое* изменение текста страницы целиком — включая правки
уже опубликованного материала, а не только полностью новый контент.

## Подключение реального API — произвольная платформа

Если у платформы нет готового коннектора, используйте `generic_api` — универсальный
REST-клиент с ручным JSON-конфигом. В `/watchlist` выберите тип «Другая платформа»
и укажите конфигурацию в формате JSON:

```json
{
  "base_url": "https://api.platform.example",
  "endpoint": "/channels/{id}/posts",
  "auth_type": "bearer_header",
  "auth_env_var": "PLATFORM_TOKEN",
  "items_path": "items",
  "field_map": {
    "external_id": "id",
    "text": "text",
    "author_label": "author.name",
    "published_at": "created_at"
  },
  "since_param": "since",
  "since_format": "iso8601"
}
```

Сам токен в БД не хранится — только имя переменной окружения (`PLATFORM_TOKEN` в примере
выше), значение которой нужно задать в `.env` (см. `.env.example`) или в окружении процесса.
Если переменная не задана — коннектор пишет понятную ошибку в лог и пропускает опрос этого
источника; остальные источники продолжают опрашиваться.

## Переменные окружения

См. `.env.example`: `POLL_INTERVAL_SECONDS` (интервал опроса, по умолчанию 20с),
`MOCK_RELEASE_INTERVAL_SECONDS`, `GENERIC_API_TIMEOUT_SECONDS`, `RISK_THRESHOLD_MEDIUM`,
`RISK_THRESHOLD_HIGH`, `SEED_DEMO_SOURCE`.
